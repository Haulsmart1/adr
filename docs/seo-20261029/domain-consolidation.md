# Domain consolidation proposal — approval required, not implemented

`adrcarriers.com` serves the Vercel public site. `adrcarriers.co.uk` and `www.adrcarriers.co.uk` both still serve a separate B12 site. The `.co.uk` sitemap uses `www` URLs; the apex homepage does not consolidate to `.com`. HTTP and `www` versions of `.com` resolve to HTTPS apex `.com`. See `domain-observations.json` for final-URL observations; redirects were followed during these reads, not changed.

`url-consolidation-plan.csv` contains 93 individually listed URLs: all 59 `.co.uk` sitemap entries, the legacy `/index` path found in navigation, and 33 existing `.com` URLs. Proposed matches are editorial recommendations, not activated rules. Some legacy content has no verified counterpart: retain it pending review rather than sending every path to the homepage. Booking, scheduling, cancellation, unsubscribe and rescheduling paths need workflow review; no action endpoints were invoked for the content crawl. Public team-profile names are not assumed to be current employees.

Before any migration, Stuart must approve the canonical domain, each redirect/retention decision, any content retirement and the release itself. Verify ownership and administrator access to both hosts. Export existing B12 content and any available analytics/backlinks, review destination equivalence and migrate useful material before redirecting. Check legal/privacy content and form expectations separately. Do not merge an order/booking workflow into a quotation form without an explicit decision. The battery waste and non-ADR pallet offerings need capability review before destinations can be considered equivalent.

After approval, implement one-hop permanent redirects on the **old host**, using exact path mappings (including legacy case-sensitive paths such as `/Express-Pallets`). Normalize old apex/`www` and HTTP/HTTPS consistently, preserve relevant query semantics and fragments in links where applicable, and avoid chains or loops. Do not redirect unknown or unrelated paths to the homepage; use a genuine relevant destination or an approved 404/410 decision. Do not block the old URLs in robots.txt before crawlers can see their redirects. Preserve existing `.com` service URLs.

Then verify every mapped source and destination, TLS, sitemap, canonicals, internal links and form behaviour; submit the new sitemap and use Search Console’s migration tools only where applicable. Monitor coverage, selected canonicals, old-host requests, 404s and qualified enquiries. Keep the old domain and redirects available long term. No DNS record, live redirect, B12 setting or Search Console setting is modified by this work.
